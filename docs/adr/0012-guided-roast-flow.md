# ADR 0012: A guided roast without a modal wizard

## Status
Proposed (2026-11-08)

## Context
Feedback from the first supervised roasts asked for a guided flow: choose
beans and amount, pick a goal (espresso, filter, own), set target values, state
clearly whether this is the simulator or the real roaster, show a plan, roast,
then record the weight, notes and cupping and compare with the plan.

During a roast the hands are at the machine and the eyes are on the curve. A
multi-page wizard that takes over the screen would get in the way exactly then.
Hands-on use also showed that what is needed live is small: one chart, the
controls, and the next event as one big button.

## Decision
The guide is three short steps around one live screen, not a wizard that
replaces it.

1. **Before** (extends the existing start dialog): beans, green weight, goal and
   target values (drop temperature, development time or DTR as a percentage),
   all optional with sensible defaults. The machine line states **Simulator** or
   **Real roaster** and is never skipped. A reference roast chosen here becomes
   the plan: its curve is drawn as the target line. Targets are editable and are
   suggestions, not limits; the safety layer does not read them.
2. **During**: the live screen stays as it is. Events are marked in their
   natural order with one primary button; every event can be undone. The AI may
   propose changes as notes the person can follow or ignore; nothing happens
   without a lease, as before.
3. **After**: the drop saves the roast and opens a small dialog for the roasted
   weight with the weight loss shown live. Notes, cupping and comparison with the
   plan live in the archive, where a roast can be edited at any time.

Data: the plan is stored with the roast as `plan` (goal, drop temperature,
development target) next to the existing batch data, in the open roast file
(ADR 0008). Whether a roast came from the simulator is recorded in its origin
and shown permanently on the roast screen and in the archive; a simulated roast
can never be mistaken for a real one.

## Not now
- Bean lots and stock (belongs to M4 with inventory).
- Cupping forms (M4).
- A plan generated by the AI. The first plans come from a chosen reference roast.

## Consequences
- The live screen keeps its single job; nothing new blocks it.
- Each step is small and can ship on its own: simulator/real badge, goal and
  targets in the start dialog, plan line on the chart, archive comparison.
- The roast file gains an optional `plan` field; older files stay valid.
