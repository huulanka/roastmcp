# Security and safety reports

## What to report privately

- Anything that lets a command reach a roaster without passing the safety layer.
- Ways for an AI client to act without a lease, without presence confirmation,
  or after an emergency stop.
- Access to the local API or MCP endpoint without the token, or from another
  machine.
- Data loss or corruption in the database, roast files or backups.

Please use GitHub's **private vulnerability reporting** ("Report a
vulnerability" on the Security tab) instead of a public issue. You will get an
answer within a week.

## Supported versions

Until 1.0, only the latest release receives fixes.

## Physical safety

RoastMCP never replaces supervision. If you see a roaster behave dangerously,
use the machine's own controls or cut its power first, then report.
